# Web demo

"LaLiga 2015/16 In Depth": a static, interactive site built on
precomputed StatsBomb data. Full 2015/16 standings, every player who
played that season, and all 380 matches, plus a nine-player
season-over-season trend using a second season (2014/15). No backend, no
API calls once loaded, and `FootballDataClient` is intentionally
excluded, see the Methodology section on the page itself for why.

Plain HTML/CSS/JS, [Plotly.js](https://plotly.com/javascript/) for the
generic charts, hand-rolled SVG/D3 for the three pitch maps (shot map,
passing map, defensive-action map). No frontend build step.

## Building the data

The page reads static JSON from `public/data/`, generated by
`scripts/data_pipeline/`, not committed to the repo. From the project
root, with the package installed (`pip install -e ".[dev]"`):

```bash
python -m scripts.data_pipeline.build
```

This fetches from StatsBomb's open data for every player and all 380
matches of the season, so the first run takes some time (roughly 15-20
minutes). Repeated runs reuse a local disk cache at `.cache/statsbomb/`
(StatsBomb's open data never changes once published, so there's nothing
to invalidate), making later runs much faster.

## Previewing locally

`fetch()` can't load local JSON over `file://`, so serve this directory
over HTTP. From the project root:

```bash
python -m scripts.serve_webapp
```

Then open <http://localhost:8000>. This is `http.server` with browser
caching turned off: plain `python -m http.server` lets the browser keep
old copies of some JS files after an edit, and a mix of old and new files
leaves the page blank.

## Deploying

`.github/workflows/deploy-pages.yml` builds the data and deploys this
directory to GitHub Pages on every push to `main` that touches
`webapp/`, `scripts/data_pipeline/`, or `football_analytics/`. Enable it
once under the repository's Settings > Pages > Build and deployment >
Source = "GitHub Actions".
